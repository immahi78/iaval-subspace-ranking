# IAVAL subspace ranking: uncertainty-aware, explainable ranking of rare objects (simulated demo)

> **All data here are SIMULATED.** The catalogue is generated by `src/iavalss/simulate.py` as a toy
> stand-in for a quasar catalogue. It contains **no DESI data** and the results are **not** findings
> about real quasars.

Author: Maheen Anwar (BSc Hons Astrophysics, MSc GIS, University of Karachi).
Prototype for the discovery layer of my PhD idea **IAVAL** (see also
[`iaval-demo`](../iaval-demo) for the sky-map / systematics stage).

## What it does
1. **Subspace scoring.** For every pair of catalogue properties (10 properties, 45 projections) computes
   interpretable scores (density contrast, distribution deviation, local outlyingness), rank-normalises
   them and combines them with adjustable weights into an object score I.
2. **Uncertainty.** Each object is re-drawn within its own per-property measurement errors; the share of
   draws in which it stays in the anomalous tail gives P(anomaly | x, sigma).
3. **Data quality.** An artefact probability from S/N and quality flags down-weights objects that are
   probably instrumental.
4. **Explanation + export.** Each candidate gets a plain-language reason (projections, which score,
   which properties, sigma offsets) and is exported as CSV and VOTable for TOPCAT.
5. **Evaluation** against injected truth: precision/recall at k, ablation, weight sensitivity, rank
   stability, versus random, Mahalanobis and Isolation Forest baselines.

## Results (simulation, seed 42, 50,000 objects; copied from `outputs/results.txt`)
Truth: 500 dusty-reddened + 400 BAL-like rare objects (1.8% of the catalogue) and 200 artefacts.

| Method | P@100 | P@200 | P@500 | P@1000 | artefacts in top 500 |
|---|---|---|---|---|---|
| random | 0.02 | 0.02 | 0.02 | 0.016 | 0.002 |
| Mahalanobis | 0.03 | 0.085 | **0.254** | **0.299** | 0.390 |
| Isolation Forest | 0.13 | 0.19 | 0.228 | 0.217 | 0.258 |
| IAVAL plain score | 0.15 | 0.125 | 0.118 | 0.115 | 0.120 |
| **IAVAL aware (full)** | **0.39** | **0.30** | 0.188 | 0.146 | **0.042** |

**Honest reading.**
- At the top of the list (the first 100 to 200 candidates a person would actually inspect) the aware
  score is clearly best, and it puts far fewer artefacts in the top 500 (4% vs 26% to 39%).
- Deeper in the list (top 500 and 1000) the simple Mahalanobis distance has **higher precision**; the
  aware score trades some of that for artefact suppression.
- The ablation shows both stages matter: removing the data-quality stage lets artefacts back in (20% of
  the top 500) and removing the uncertainty stage lowers P@100 from 0.39 to 0.24.
- Rank stability is **lower** for the aware score (top-500 Jaccard 0.30 across re-drawn catalogues, vs 0.50
  for Mahalanobis). The Monte Carlo step is stochastic and the shortlist is small, so this needs work.
- Aware-score precision depends on the weights (P@500 ranges 0.11 to 0.22 over random Dirichlet weights).
- The demo takes about 90 seconds; the aware score costs about 28 s here vs 0.03 s for Mahalanobis.

## Run
```bash
pip install -r requirements.txt
python scripts/run_demo.py      # writes docs/figures, outputs/results.txt, candidates CSV + VOTable
python -m pytest -q tests
```
Open `outputs/candidates_topcat.csv` or `candidates.vot` in TOPCAT.

## Limitations
- Simulated data with simple distributions and a simple error model; no real systematics.
- The artefact model is told roughly what artefacts look like (low S/N, flags), as in the simulation.
- A single seed for the headline table; the stability table uses two re-drawn catalogues only.
- Nothing has been run on DESI DR1.

## Next steps
